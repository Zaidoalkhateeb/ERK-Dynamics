# Client handoff

## Deliverables

- Source repository with `package-lock.json`, `.env.example`, and these maintenance documents.
- A fresh `dist.zip` built from the same source revision, if the client is deploying immediately.
- Access to the hosting control panel, domain/DNS, company inbox, and Git repository, transferred through the agreed account process.

## Acceptance checks

- Run `npm ci`, `npm run check`, `npm run test:php`, and `npm run dist` from a clean checkout.
- Review desktop and phone layouts, navigation, all four product pages, and industry details.
- Confirm real delivery from both forms on the PHP host.
- Confirm the canonical domain and company contact details.
- Record the source revision and deployment date, and retain the previous deployment for rollback.

## Content items to confirm with the client

The existing homepage says **three global technology partners**, while the published partner cards and directory name **Auxivo and LEICE**. The cleanup preserves the supplied business claim; confirm whether a third partner should be added or the statistic changed.

Product specifications, certifications, and performance claims still need approved manufacturer material. The product pages currently explain that detailed technical values will be published from approved documentation.

Confirm permission to transfer and publish the supplied product photographs, partner logos, globe textures, and Helvetica font files. License or ownership records for those assets are not included in this repository.

## Supported scope

This is an English-language marketing site with enquiry forms. No Turkish translation, CMS, online checkout, CRM connection, analytics integration, attachment delivery, or visitor email confirmation is implemented. Outbound LiDAR and power-supply links go to Think Metric.

The code cleanup prepares the source for maintenance and handoff. Hosting credentials, domain ownership, actual inbox delivery, and client content approval remain part of deployment acceptance.
